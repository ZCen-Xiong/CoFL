## 1. 任务纠正与已确认约束

当前明确要求先按 CoFL-S 流程生成质点 F(x,y)：无语言、手动起终点、低相机
高度（当前示例 0.2m）、墙面净空可配置且默认 0.02m。之后再在 COG 附近选择
相关质点的流线作为端点运动规划，不在此阶段把整机外形嵌入场的可行域。

此前实现的 `(x,y,q)`、整机胶囊十字碰撞、q 切片和 Fq 是对用户方案的误解，
已从当前网页与采集链路移除，不能继续当作当前任务约定。旧构型算法和历史
数据仅为保留代码/产物，不参与质点场。后面的硬件约束不意味着已恢复整机场。

2026-11-22 用户明确授权实现 A 路线并运行数据采集、teacher、DFormer 短训练

## 3. 数值、参数与坐标

原算法先按质点硬净空定义自由空间；8 邻接图使用原 CoFL-S 安全代价。
从目标计算代价距离和沿同一前驱树的几何长度，再构造势函数和负梯度，
按原方法平滑方向，幅值为几何距离/v_norm（默认 5m）。不是上一版单位构型切向量。
terminal 为零；不可达不标作 STOP；inf 不得作为有限监督送入 loss。

Studio 顶层参数：cofm_point_clearance_m=0.02、cofm_field_resolution_m=0.025、
cofm_safety_band_m=0.02、cofm_safety_cost_weight=5。安全带是软成本，不是再次
膨胀机体。箭头默认隔 4 个场格抽样，并有显示数量上限，不能据留白直接测净空。

重导入必须 agent_radius=0；旧非零侵蚀的 MP3D 清单会拒绝用于质点 teacher，
避免隐藏的重复 clearance。当前新结果 matterport-point-020 使用 1cm 占据格。
point_clearance 使用 EDT 对占据单元面积的保守下界与 Lipschitz 点查询，不把
质点扩大成整机或矩形；仍存在栅格量化误差，不能保证距真实网格恰好 20mm。

规划为 x 前、y 左、z 上；Habitat Y 上、相机默认看 -Z。MP3D 映射：

```text
Xh = -(y + origin_y)
Yh = floor_y + config.camera_height
Zh = -(x + origin_x)
```

场的磁盘轴为 [Ny,Nx,2]；原 CoFL-S 数值函数按行=forward、列=left，因此适配
时转置空间轴，通道仍为 Fx/Fy。局部相机朝向 ψ：
forward=cosψ dx+sinψ dy，left=−sinψ dx+cosψ dy，向量与目标同样旋转。
RGB-D 对齐 320×240、HFOV 90°、0.05–15m；深度是米制光轴 Z，非射线距离。

## 9. 硬件约束与代理边界

本节保留硬件资料；其中十字代理是此前停用的构型场简化，不参与当前质点场生成。

以下保留原硬件说明中的约束，资料来源为本地
`aei4249_CombinedPDF_v18.pdf` 的正文 §2.1、§3.2、§4.1–4.2。
这些值描述论文原型机；本文合并时未重新做 CAD/实机标定，不能把论文值或
简化代理当成用户现机的最终标定。完整约束整理如下。

### 1. 机械结构

- AMREBA 是四臂十字形变形无人机。四条臂沿机体系水平面内的 `+X、+Y、−X、−Y` 方向布置；从 `+X` 开始逆时针编号为 Arm 1–4。
- 四臂采用 Bi-RCA（bi-rigid chain actuator）共享刚性链结构。每条臂由两条配对刚性链构成，部署后形成可承载的直线伸缩臂。
- 相邻机械臂共享链段，链段经中心链轮重新分配；同步齿轮与减速齿轮由**一个中央舵机**驱动。
- 四臂共有 **1 个机械变形自由度**，不是四个独立伸缩自由度。
- 每条臂末端装有一套可绕该臂纵轴倾转的涵道旋翼；四个旋翼各有独立推力输入和独立倾转角输入。
- 机体有用于向内夹持的接触点（Arm 1、3）和用于向外支撑/推压的接触点（Arm 2、4），顶部可安装任务工具。

### 2. 变形运动学与硬约束

定义 `e_i` 为机体中心到第 `i` 个旋翼中心的距离，`q` 为共享变形坐标，`e0 = 0.30 m`。

```text
e1 = e3 = e0 + q
e2 = e4 = e0 - q
-0.10 m <= q <= +0.10 m
sum(e1, e2, e3, e4) = 1.20 m
```

- `q > 0`：Arm 1、3 伸长，Arm 2、4 缩短。
- `q < 0`：Arm 2、4 伸长，Arm 1、3 缩短。
- `q = 0`：四臂等长，每个旋翼中心距机体中心 `0.30 m`。
- 原型机的旋翼中心距范围为 `0.20–0.40 m`；上述边界是论文所述可用运动行程的近似数值表示。
- 机械臂沿各自固定轴线平移伸缩；变形过程中臂的方位不发生关节旋转。
- 规划器必须保持对臂等长和总长度守恒；不能独立给四臂指定长度，也不能同时缩短两个正交臂对。

### 3. 飞行与倾转运动能力

- 机体位姿为 `SE(3)`：三维位置 `(x,y,z)` 与三维姿态（roll、pitch、yaw）。
- 四个旋翼提供独立推力 `f1..f4`；四个倾转舵机提供独立角度 `alpha1..alpha4`。
- 每个旋翼绕对应机械臂的局部纵轴倾转；`alpha_i = 0` 时推力沿机体局部 `+Z` 方向。
- 论文给出的倾转机构硬件行程为 `alpha_i ∈ [-1.5π, 1.5π] rad`。
- 旋翼推力与倾转方向联合提供机体的三维力和三维力矩，支持六自由度全驱动飞行及姿态调整；论文展示了从 `0°` 到 `180°` 的滚转运动。
- 变形与飞行可以协同执行，例如在保持指定航向的同时平移并调整机体外形。

### 4. 规划所需的状态和几何边界

建议将最小规划构型写为：

```text
configuration = (position_xyz, orientation_SO3, q)
```

若规划器同时计算飞行动力学和执行器命令，可另引入机体速度、角速度、四个旋翼推力与四个倾转角等状态/输入。

- **碰撞几何**：应使用机体中心结构、四条伸缩臂、涵道旋翼以及实际接触附件的组合外形；`e_i` 仅定义旋翼中心位置，不是机器人外轮廓半径。
- **变形包络**：外形随 `q` 连续改变，通道穿越时需要检查整个机体与障碍物的间隙，以及变形和运动过程中的扫掠体积。
- **几何示例（论文原型机）**：等长构型的两轴外宽约为 `0.77 m`（Arm 1/3 方向）和 `0.80 m`（Arm 2/4 方向）；对应轴充分缩短时外宽约为 `0.57 m` 与 `0.60 m`。两轴尺寸不同源于末端附件。
- **接触任务**：Arm 1/3 的向内夹持与 Arm 2/4 的向外支撑受同一个 `q` 耦合；夹住物体后，夹持宽度会限制后续变形范围。
- **动力学**：实际控制采用考虑舵机的 NMPC；论文在每个预测时域内将伸缩视为准静态，并固定该时域的几何相关惯性参数。此项是原控制模型假设，规划器可据任务精度决定是否沿用。

### 5. 对研究计划的直接约束

1. 变形决策变量使用单一 `q`，并通过耦合方程生成四个旋翼中心位置。
2. 路径规划需要联合考虑 `SE(3)` 位姿与 `q`，至少进行随构型变化的机体碰撞检查。
3. 飞行运动能力由四旋翼推力和四倾转角提供；规划层可先输出参考位姿与 `q`，由底层 NMPC 跟踪。
4. 需要执行器级可行性时，再加入推力、倾转速度、变形速度和动力学限制；本文未给出这些量的统一可直接采用的规划边界，不应自行假定数值。

**边界原则：** 当前硬件为「6-DoF 机体运动 + 1-DoF 耦合变形 + 4 个独立旋翼倾转机构」。其中倾转机构服务于飞行力/力矩分配，不代表四条伸缩臂可独立变形。

### 当前几何代理与硬件资料的区别

代码使用横纵对称的胶囊十字：中心线端点为 `e0±q`、圆帽半径 0.10m，得到两轴外长 `0.80±2q` 米。它没有逐件还原论文中 0.77/0.80m 的不对称附件，也未建模旋翼倾转后的三维外形。停泊并集和扫掠保证仅针对该代理，硬件更换、附件或转体任务需重建包络并重新验证。

## 10. 过往 Transformer 学习讨论的接续约定

本节汇总此前学习上下文中仍有用的符号和沟通约定，不参与当前生成流程。
先前讨论依据用户提供的 Transformer Q/K/V 推导 PDF；沿用该 PDF 编号，
不能用 2017 encoder–decoder 示意图替代其 decoder-only、causal、Pre-LN 顺序。

用户关心每步的具体输入、输出、矩阵尺寸、固定权重与动态值，已经理解基本
矩阵乘法。讲解时区分 Attention 的跨 token 信息汇集、MLP 的逐 token 非线性、
Residual 的保留/梯度路径和 LayerNorm 的归一化。

过往示例使用 GPT-3 175B 一类尺寸，不是 DFormer 或所有模型的配置：

| 符号 | 示例值与含义 |
| --- | --- |
| n | 3 个 token，例如“我、喜欢、苹果” |
| d | 12288，hidden width |
| m / d_h | 96 个 head，每个 128 维 |
| d_ff | 49152，即 4d，事先定义的 MLP 中间宽度 |
| L | 96 个 block |
| N_v | 约 50000，词表大小 |

每 token 对应矩阵一行，`X∈R^(n×d)`。保留原 PDF 的步骤映射：

| 步骤 | 运算 |
| --- | --- |
| 1–2 | 标注规范和维度约定 |
| 3 | tokenization 得到 token ID |
| 4 | 从 `W_E[N_v,d]` 查表得到 embedding |
| 5 | 加位置信息，示例 `X=E+P`；其他模型可能用 RoPE |
| 6 / 6.1 | 进入 block，先做 `LN_1(X)` |
| 7 | 每头投影 Q/K/V，分别 `[n,d_h]` |
| 8 | `QKᵀ/sqrt(d_h)`，得到 `[n,n]` 分数 |
| 9 | causal mask，禁止未来 token |
| 10 | 每行 softmax 得到注意力权重 A |
| 11 | `AV`，每头 `[n,d_h]` |
| 12 | 拼接所有 head，得到 `[n,d]` |
| 13 | 输出投影 `W_O` |
| 14 | 第一次残差加法 |
| 15.1–15.4 | `LN_2` → Linear d→d_ff → GELU → Linear d_ff→d |
| 16 | 第二次残差加法 |
| 17 | 重复 L 层，得到 `X^(L)` |
| 18 | final LN，取最后位置 hidden state |
| 19 | 输出词表投影 `W_U[d,N_v]` 得到 logits |
| 20 | softmax/decoding，选择下一个 token ID |

Attention 输出并非已完成下一个 token 预测，后续 MLP、残差和输出头仍是
已训练架构的一部分。`X^(96)` 是第 96 层后的全部 token 表示，不是词表概率。
logits 是未归一化分数；输入输出 token ID 共用同一词表含义，但 `W_E` 与
`W_U` 是否共享权重要看具体实现，不能从维度相容就推断已经绑定。
LN 的均值/方差按样本动态计算，缩放/偏置可学习；残差加法本身无可学习权重。
KV cache 缓存已有位置的 K/V，不等于输出概率或最终 hidden state。
